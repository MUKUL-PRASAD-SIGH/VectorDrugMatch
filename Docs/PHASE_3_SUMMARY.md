# VectorDrugMatch — Phase 3 Summary

This document explains the architecture, components, and research methodology implemented up to **Phase 3 (Classical ML Baselines & Scoring)**. 

## 1. Project Architecture

The project has been refactored from a collection of ad-hoc scripts into a modular, research-grade Machine Learning pipeline.

**Core Principles:**
- **Strict Separation of Concerns:** Preprocessing does not do training. Feature extraction does not know about models.
- **Single Source of Truth:** `scripts/preprocess.py` creates the base CSVs. All downstream scripts read exclusively from `data/processed/`.
- **Reproducibility:** Seeded random states, automated edge sampling, and CLI-driven orchestration.

### Directory Structure
```
data/
  ├── raw/         (Immutable source files)
  └── processed/   (Generated by preprocess.py)
scripts/           (Orchestration entry points)
src/
  ├── data/        (Graph & dataset building, negative sampling)
  ├── features/    (Domain-specific engineering: drug, disease, pairs)
  ├── models/      (BaseModel interfaces and ML implementations)
  ├── scoring/     (NDPI components: similarity, equity, literature)
  └── utils/       (Metrics, etc.)
```

## 2. Tabular ML Pipeline (Phase 3)

In Phase 3, we train classical Machine Learning models (Logistic Regression, Random Forest, XGBoost). 
**Crucial Distinction:** These tabular models *cannot* consume a graph structure directly. They require flat 1D feature vectors representing the Drug-Disease pair.

### The Pipeline Flow:

1. **Node Feature Engineering (`src/features/drug.py`, `src/features/disease.py`)**
   - **Drugs:** Encoded into 2048-bit Morgan Fingerprints via RDKit (shared across ALL models to ensure fair comparison).
   - **Diseases:** Encoded using WHO DALY burden normalizations and NTD categorical flags.

2. **Negative Edge Sampling (`src/data/negative_sampling.py`)**
   - The graph only contains *positive* treatment edges (CtD). A binary classifier needs negative examples (drugs that *don't* treat a disease).
   - This module explicitly samples negative edges (at a configurable ratio, e.g., 1:5) while ensuring they do not collide with known positive edges.

3. **Pairwise Feature Generation (`src/features/pair.py`)**
   - Converts `Drug Node` + `Disease Node` into a single `X` training vector.
   - We use feature concatenation (`[Drug_Features | Disease_Features]`), which allows the model to learn interaction weights.

4. **Train/Val/Test Splits (`src/data/dataset.py`)**
   - We explicitly separate data into **Train (70%), Validation (15%), and Test (15%)** splits. 
   - This split is stratified to maintain the positive/negative class balance across all sets.
   - Reviewers demand clear evaluation boundaries; the Test set is kept entirely unseen during `model.fit()`.

5. **Model Orchestration (`scripts/train_baselines.py`)**
   - Orchestrates the above steps.
   - All models inherit from a common `BaseModel` (`src/models/baseline/base.py`) providing standard `train()`, `predict_proba()`, `save()`, and `load()` methods.
   - Uses `--model default` to only train **Logistic Regression, Random Forest, and XGBoost** initially. MLP is reserved until the tabular pipeline is fully proven, as complex NNs require significant tuning on tabular data.

## 3. NDPI Scoring Architecture (`src/scoring/`)

The NDPI (Neglected Disease Priority Index) is separated entirely from the ML feature engineering. This prevents **data leakage**.

- `similarity.py`: Calculates Tanimoto chemical similarity to known treatments. **This is NOT used as an ML feature.** If it were, the model would simply learn to output high probabilities for highly similar drugs, and adding the similarity score *again* later in the NDPI calculation would double-count the signal.
- `literature.py`: Biopython NCBI Entrez wrapper with SQLite caching to count co-occurrences of the drug and disease in PubMed.
- `equity.py`: Public health proxy using DALY burden, EML status, and Molecular Weight (as a proxy for manufacturing affordability).

These modules are purely standalone scoring functions that will be queried during Phase 6.

---

## 4. Summary of Improvements over Initial Design

1. **Modular Dataset Generation:** Separated `dataset.py` and `pair.py` from the training script so all models are guaranteed to train on identical splits.
2. **Dedicated Negative Sampling:** `negative_sampling.py` ensures the exact same negative logic is used everywhere, preventing implementation drift.
3. **CLI Arguments:** `train_baselines.py` is now a proper CLI tool (`--model all`, `--model rf`).
4. **Base Interfaces:** `BaseModel` enforces a clean ML engineering API across all baseline estimators.
5. **Clear Graph vs Tabular Distinction:** Established that classical models explicitly operate on constructed `X` vectors, paving the way for a fair and clear comparison against the upcoming Phase 4 GNNs which operate on topological message passing.
